## 4주차: JavaScript 실습

* 장소 탐험 페이지: 
* 통계 페이지: https://본인아이디.github.io/저장소/week4/statistics.html
* 게임 페이지: https://본인아이디.github.io/저장소/week4/game.html

### 실습 1

* 내가 수정한 부분:

  * 기존 Week 2에서 사용했던 세 장소의 사진, 설명, 선택 이유를 Week 4 장소 탐험 페이지에 추가했습니다.
  * 세 개의 버튼을 만들고 버튼을 클릭하면 해당 장소의 내용이 표시되도록 수정했습니다.
  * 선택한 장소에 맞는 Google Maps 지도가 표시되도록 JavaScript를 작성했습니다.

* 버튼 클릭 → 내용 변경 → 지도 변경의 흐름:

  * 버튼을 클릭하면 JavaScript의 `click` 이벤트가 실행됩니다.
  * 버튼의 `data-place` 값을 이용하여 해당 장소를 찾습니다.
  * 선택하지 않은 장소는 `hidden`으로 숨기고 선택한 장소만 표시합니다.
  * 버튼의 `data-map` 값을 이용하여 Google Maps iframe의 주소를 변경합니다.

* 휴대전화에서 확인한 결과:

  * 휴대전화에서 GitHub Pages의 장소 탐험 페이지를 열어 세 장소 버튼을 확인했습니다.
  * 버튼을 눌렀을 때 장소 설명과 지도가 정상적으로 변경되는 것을 확인했습니다.

### 실습 2

* 데이터 출처 URL / 내려받은 날짜:

  * 데이터: 서울시 도시데이터 센서(S-DoT) 유동인구 설치 위치정보
  * 내려받은 날짜: 2026년 9월

* 데이터 선택 이유 / 대상·기간·단위:

  * 서울시에 설치된 S-DoT 센서의 위치 분포를 확인하기 위해 선택했습니다.
  * 데이터에는 센서의 주소, 위도, 경도 등의 정보가 포함되어 있습니다.
  * 센서 설치 위치를 기준으로 지역별 센서 수와 위치 분포를 확인했습니다.

* 그래프 1: 질문 / 사용한 열 / 그래프 형식과 선택 이유 / 해석:

  * 질문: 서울시의 각 지역에 설치된 S-DoT 센서는 몇 개인가?
  * 사용한 열: `주소`
  * 그래프 형식: 막대그래프
  * 선택 이유: 지역별 센서 수를 비교하기 쉽기 때문에 막대그래프를 사용했습니다.
  * 해석: 각 지역에 설치된 센서의 개수 차이를 확인할 수 있습니다. 센서 수는 실제 유동인구의 크기를 의미하지 않습니다.

* 그래프 2: 질문 / 사용한 열 / 그래프 형식과 선택 이유 / 해석:

  * 질문: 서울시에서 S-DoT 센서는 어떤 위치에 분포되어 있는가?
  * 사용한 열: `위도`, `경도`
  * 그래프 형식: 산점도
  * 선택 이유: 위도와 경도를 좌표로 표시하여 센서의 위치 분포를 확인하기 위해 사용했습니다.
  * 해석: 서울시 내 센서의 전체적인 위치 분포를 확인할 수 있습니다. 이 그래프도 실제 유동인구의 많고 적음을 나타내지는 않습니다.

* 필터링·집계·결측치 처리:

  * 주소가 없는 데이터는 지역별 센서 수 계산에서 제외했습니다.
  * 위도와 경도가 숫자로 변환되지 않는 데이터는 위치 그래프에서 제외했습니다.
  * 주소에서 `구`를 추출하여 지역별 센서 수를 집계했습니다.

* 두 탭 전환 방식:

  * JavaScript의 `click` 이벤트를 사용하여 두 그래프를 전환했습니다.
  * 선택하지 않은 그래프에는 `hidden` 속성을 적용하고 선택한 그래프만 표시했습니다.
  * `aria-pressed`를 이용하여 현재 선택된 탭을 표시했습니다.

* 휴대전화에서 두 탭을 확인한 결과:

  * GitHub Pages에서 통계 페이지를 열고 두 탭을 각각 눌러 그래프가 정상적으로 표시되는지 확인했습니다.

* 빈 데이터·잘못된 CSV를 넣었을 때 결과:

  * CSV 파일을 정상적으로 읽을 수 없으면 콘솔에 오류가 표시되도록 작성했습니다.

* Copilot 활용:

  * Papa Parse를 이용한 CSV 읽기와 Chart.js를 이용한 그래프 작성 방법을 참고했습니다.
  * CSV의 열 이름과 데이터 형식에 맞게 JavaScript 코드를 직접 수정하고 GitHub Pages에서 결과를 확인했습니다.

### 실습 3

* 게임 이름 / 아이디어 / 조작과 규칙:

  * 게임 이름: 클릭해서 점수 얻기
  * 화면에 나타나는 목표를 클릭하면 점수가 1점 증가합니다.
  * 게임 시간은 20초이며 시간이 끝나면 게임이 종료됩니다.
  * 게임 종료 후 최종 점수를 확인하고 다시 시작할 수 있습니다.

* Copilot에게 보낸 첫 질문:

  * Canvas를 이용하여 화면에 나타나는 목표를 클릭하면 점수를 얻는 간단한 JavaScript 게임을 만들어 달라고 요청했습니다.

* 추가 수정 요청과 개선한 점:

  * 게임 시작 버튼과 다시 시작 버튼을 추가했습니다.
  * 점수와 남은 시간을 화면에 표시하도록 수정했습니다.
  * 목표가 클릭될 때마다 다른 위치로 이동하도록 수정했습니다.
  * 휴대전화에서도 사용할 수 있도록 Canvas 크기와 버튼을 반응형으로 수정했습니다.

* 직접 확인한 동작: 조작 / 점수 / 종료 / 재시작:

  * 게임 시작 버튼을 클릭하면 게임이 시작됩니다.
  * 목표를 클릭하면 점수가 증가합니다.
  * 20초가 지나면 게임이 종료되고 최종 점수가 표시됩니다.
  * 다시 시작 버튼을 클릭하면 게임을 다시 시작할 수 있습니다.

* 휴대전화에서 확인한 결과:

  * GitHub Pages의 게임 페이지를 휴대전화에서 열어 게임 시작, 목표 클릭, 점수 증가, 종료 및 다시 시작 기능을 확인했습니다.

* 이미지·소리 출처와 이용 조건(사용한 경우):

  * 별도의 이미지나 소리를 사용하지 않았습니다.
  * Canvas로 게임 화면을 직접 구성했습니다.
